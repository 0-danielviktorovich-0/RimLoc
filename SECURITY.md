# Политика безопасности RimLoc

Обновлено: 2026-10-06.

RimLoc находится в pre-beta и ещё не обещает долгосрочную поддержку старых сборок. Исправления безопасности в первую очередь попадают в текущую линию разработки и ближайший тестовый/публичный релиз.

## Поддерживаемые версии

| Версия / линия | Статус |
| --- | --- |
| Текущая активная разработка | поддерживается |
| Последний актуальный pre-release после начала beta | поддерживается |
| Старые alpha/dev-сборки | best effort; сначала воспроизведите на актуальном коде |
| Исторические теги | не backport-ятся по умолчанию |

## Как сообщить об уязвимости

**Не публикуйте рабочий exploit или чувствительные детали в обычном issue.**

Предпочтительный канал — GitHub Security → **Report a vulnerability / Private Vulnerability Reporting** для репозитория RimLoc.

Если приватная форма недоступна, создайте минимальный публичный issue **без технических деталей эксплуатации** и попросите приватный канал.

Полезно приложить:

- commit/tag/build identity;
- ОС и способ запуска (CLI/desktop);
- минимальный воспроизводимый пример;
- точные шаги;
- затронутые пути/файлы;
- логи после удаления секретов и персональных данных.

## Что считается особенно важным

В scope входят:

- запись за пределы явно разрешённого output/project storage;
- path traversal / symlink escape;
- выполнение произвольных shell-команд через desktop/IPC;
- чтение неожиданных локальных файлов;
- утечка provider/API secrets;
- небезопасные Tauri capabilities или production debug/automation hooks;
- parser/format input, который приводит к security-impact, а не только к обычной ошибке;
- уязвимые production-зависимости, реально достижимые из RimLoc.

Не относятся к RimLoc:

- уязвимости самой игры RimWorld;
- вредоносный C#-код внутри мода, который исполняет уже RimWorld;
- проблемы стороннего LLM/MT-провайдера на его стороне;
- обычные баги без security impact.

## Текущий pre-beta security gate

GitHub Dependabot/Code Scanning и локальные Rust/JS dependency-аудиты сейчас проходят отдельную сверку против актуальной React/Rust линии.

**Не используйте старые числа из historical audit-документов как текущий публичный security verdict.** До beta цель:

- 0 известных эксплуатируемых Critical;
- 0 известных эксплуатируемых High;
- 0 утечек секретов;
- 0 известных выходов записи из разрешённых путей;
- 0 automation/debug backdoors в production artifact.

Актуальная инженерная детализация хранится в:

- <code>docs/security/PRE_BETA_SECURITY_AUDIT.md</code>
- <code>docs/security/CODE_SCANNING_RECONCILIATION.md</code>
- <code>docs/security/DEPENDABOT_RECONCILIATION.md</code>

Эти файлы являются рабочими audit-артефактами и могут меняться быстрее, чем публичная политика.

## Disclosure

Проект поддерживается небольшим числом людей, поэтому SLA не гарантируется. Мы постараемся подтвердить получение приватного репорта в течение 7 дней и не публиковать детали до подготовки исправления.

Если отчёт подтвердится, мы по возможности координируем исправление, advisory и публичное раскрытие с исследователем.
