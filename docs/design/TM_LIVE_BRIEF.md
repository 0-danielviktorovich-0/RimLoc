# БРИФ ВЛАДЕЛЬЦУ — TM live (семантика)

## Контекст

TM (translation memory) — единственный домен, не собранный в живой контракт.
Бэкенд-инфраструктура готова (project_glossary CRUD показал паттерн), но
семантика TM требует вашего решения: что именно значит «live» для TM.

## Три варианта (A/B/C)

### A. Авто-пополнение из принятых переводов

- Каждая транзакция `project_apply_intents` (set_translation) добавляет
  запись в TM: {source_text, target_text, locale}.
- TM хранится внутри управляемого проекта (как glossary, serde default).
- Workspace editor показывает TM-подсказки рядом с редактором.
- Контракт: `project_tm_list` / `project_tm_search {query, locale}` /
  `project_tm_delete` / `project_tm_clear`.
- Плюс: TM автоматически накапливается без действий пользователя.
- Минус: «мусор» в TM при отклонении правки (rejected intents).

### B. Legacy load_tm импорт

- Пользователь загружает TM-файл (CSV/PO) через UI → parse → записи
  в project TM.
- Плюс: точный контроль над содержимым.
- Минус: не автоматическое, требует действий.

### C. Ручной CRUD (как glossary)

- Пользователь добавляет/редактирует/удаляет TM-записи вручную через UI.
- Плюс: полный контроль.
- Минус: не использует основную ценность TM (автоматическое накопление).

### Рекомендация: A + C (авто-пополнение + ручной CRUD)

Это стандартная семантика CAT-инструментов (OmegaT, Trados): TM накапливается
автоматически + пользователь может управлять записями вручную.

## Impact

- Бэкенд: домен TM + контракт + персист + тесты (~2-3ч).
- Фронт: TM-вкладка live (~1-2ч).
- Итого: ~4-5ч работы после вашего решения.

## Формат ответа

Ответьте A, B, C или комбинацию (например «A+C») — этого достаточно для
старта лайны.
