# AUTO UPDATE DESIGN — обновление GUI через официальный Tauri 2 updater

Дата: 2026-09-27 · Статус: **только дизайн**. Код, конфиги и секреты этим документом не менялись.
Пререквизиты схемы версий: [VERSIONING.md](VERSIONING.md) (один номер продукта, тег `vX.Y.Z`).

## 1. Статус quo

- Updater в GUI не настроен: `tauri.conf.json` → `plugins: {}`, плагина `tauri-plugin-updater` в зависимостях нет.
- Релизные workflows «припаркованы» (9591f4f, решение владельца): триггеры — только `workflow_dispatch`.
- Дистрибуция сегодня — ручная сборка (README: GUI build guide). Пользователь обновляет приложение перестановкой вручную.
- Подписи/нотаризация macOS для дистрибуции не настроены (подтверждённых секретов нет — см. §5).

## 2. Цели и не-цели

**Цели:** пользователь GUI получает обновления STABLE-канала одним действием («Проверить обновления» в приложении); обновление подписано и проверяется перед установкой; неуспех не портит установленную версию; откат — серверный, без переустановки у пользователя.

**Не-цели:** автообновления без спроса (первая версия канала — только по кнопке); несколько каналов (beta/nightly) — задел в схеме тегов, но не в настройках; обновление CLI (cargo/crates.io — свой цикл).

## 3. Архитектура

```
main (тег vX.Y.Z) ──► release workflow (ручной dispatch)
                        │  матрица: macOS(aarch64/x86_64), Windows(x64), Linux(x64)
                        │  1. cargo tauri build (bundle + createUpdaterArtifacts)
                        │  2. подпись артефактов (.sig, minisign из секрета)
                        │  3. macOS: codesign + notarization (секреты Apple)
                        │  4. upload артефактов в GitHub Release (draft → publish)
                        ▼
             GitHub Releases: артефакты + latest.json (манифест канала STABLE)
                        ▲
                        │ HTTPS GET latest.json
             GUI (tauri-plugin-updater): check → показ апдейта → download →
             verify signature → install → relaunch
```

Механизм — **официальный updater Tauri 2** (`tauri-plugin-updater` + `tauri-action` для сборки релиза):

1. **Ключи подписи.** `cargo tauri signer generate -w <путь>` создаёт пару minisign. Публичный ключ — в `tauri.conf.json` (`plugins.updater.pubkey`); приватный — ТОЛЬКО в секретах CI. Ключ генерируется один раз и хранится у владельца (потеря = пользователи не смогут обновляться с этим pubkey).
2. **Конфиг updater** (будущая правка `tauri.conf.json`, здесь не выполнялась):
   - `bundle.createUpdaterArtifacts: true` — bundler сам производит `RimLoc-GUI.app.tar.gz` + `.sig` (macOS), NSIS-артефакт + `.sig` (Windows), AppImage + `.sig` (Linux);
   - `plugins.updater.pubkey: "<minisign pubkey>"`;
   - `plugins.updater.endpoints: ["https://github.com/0-danielviktorovich-0/RimLoc/releases/latest/download/latest.json"]`.
3. **Манифест канала.** `latest.json`: `{ "version": "X.Y.Z", "notes": "…", "pub_date": "…", "platforms": { "darwin-aarch64": {"signature": "<содержимое .sig>", "url": "<URL артефакта>"}, … } }`. `tauri-action` генерирует его автоматически; схема ручного заполнения — та же.
4. **Канал STABLE.** Один канал = последний тег `vX.Y.Z[-pre]` по VERSIONING.md. Прекоммит канала — тег; беты при необходимости заводятся отдельным манифестом `latest-beta.json`, не смешиваются в STABLE.
5. **Клиент.** Проверка — по кнопке в настройках GUI (`@tauri-apps/plugin-updater` → `check()`); найдено — карточка с версией и заметками; установка — `downloadAndInstall()` с прогрессом; после — перезапуск приложения. Фоновую автопроверку можно включить позже одной настройкой вызова `check()` — архитектура от неё не зависит.

## 4. Шаги релиза (workflow, ручной dispatch)

1. Владелец выполняет чек-лист VERSIONING §4 (версии V1–V5, CHANGELOG, тег `vX.Y.Z` от main).
2. `workflow_dispatch` релизного workflow с input `tag = vX.Y.Z`.
3. Матрица сборок: `pnpm/npm build` фронтенда → `cargo tauri build` c `createUpdaterArtifacts`.
4. Подпись updater-артефактов приватным ключом из секрета (env `TAURI_SIGNING_PRIVATE[_KEY]` + пароль — см. §5); macOS — codesign/notarization тем же прогоном.
5. Загрузка артефактов + `latest.json` в GitHub Release, помеченного тегом; публикация Release = публикация канала (до публикации Release манифест недоступен — канал не меняется).
6. Smoke: `curl latest.json` → версия совпадает с тегом; артефакты по URL отвечают.

## 5. Секреты и переменные (требуются ОТ ВЛАДЕЛЬЦА)

Наличие перечисленного ниже в секретах репозитория **не подтверждено и не предполагается** — это чек-лист того, что владелец должен завести до включения updater. Ничего из этого не создаётся и не подставляется агентами.

| Имя | Что это | Кто заводит | Примечание |
|-----|---------|-------------|-----------|
| `TAURI_SIGNING_PRIVATE_KEY` | приватный minisign-ключ updater (тело ключа) | владелец, один раз | генерация: `cargo tauri signer generate -w <file>`; публичная половина кладётся в `tauri.conf.json` |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | пароль этого ключа | владелец, один раз | нужен при каждой подписи в CI |
| `APPLE_ID` | Apple ID для нотаризации (notarytool) | владелец | macOS-дистрибуция без нотаризации = Gatekeeper блокирует .app |
| `APPLE_PASSWORD` | app-specific password для этого Apple ID | владелец | НЕ пароль аккаунта; создаётся на appleid.apple.com |
| `APPLE_TEAM_ID` | Team ID Apple Developer | владелец | параметр notarytool |
| `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY` | Developer ID-сертификат для codesign | владелец | требует платного Apple Developer Program; без него подписи нет и нотаризация невозможна |

Бюджетное замечание владельцу: macOS-путь обновлений требует действующего Apple Developer Program (сертификат + нотаризация); без него updater технически работает, но распространять .app обычным пользователям macOS нельзя.

## 6. Отказы и откат

| Ситуация | Поведение |
|----------|-----------|
| `latest.json` недоступен (нет сети, GitHub лежит) | проверка молча неуспешна; в Diagnostics — заметка «не удалось проверить обновления». Приложение работает как есть |
| Подпись артефакта не сошлась с `pubkey` | скачивание/установка **отменяются**, установленная версия не трогается (updater проверяет подпись до записи) |
| Загрузка оборвалась | установка отменяется; повтор — по кнопке; текущая версия продолжает работать |
| Пользователь отложил обновление | никакого автоприменения; предложение снова при следующей проверке |
| Плохой релиз ушёл в канал (баг, битый артефакт) | **серверный откат**: заменить `latest.json` на манифест предыдущей версии (перепубликовать Release или править манифест). Пользователи, ещё не обновившиеся, получат старую версию; обновившиеся остаются до следующего релиза — клиент не откатывается сам по дизайну (downgrade не поддерживается updater'ом) |
| Приватный ключ скомпрометирован | сгенерировать новую пару, поменять `pubkey` в конфиге, выпустить релиз с новым ключом; старые клиенты обновятся до версии с новым pubkey только вручную (их pubkey уже сменён вместе с релизом — сценарий документируется в SECURITY при случае) |
