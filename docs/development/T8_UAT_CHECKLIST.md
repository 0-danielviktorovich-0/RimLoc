# T8 — UAT-чеклист: интерактивная приёмка нативных файл-пикеров (7 контролов)

T8 закрывает то, что pure-AX lane (`testlab/ui_automation/lane_native_pickers.py`)
не может в фоновой сессии: выделение строки и подтверждение «Открыть» внутри
NSOpenPanel (UI_DEFECTS_MATRIX PK-01/PK-02/PK-05 → deferred to T8 CUA / owner UAT).
Сессия интерактивная — приложение в фокусе, с явного согласия владельца.
Источники: CONTROLS в `lane_native_pickers.py`; дефекты —
`docs/development/UI_DEFECTS_MATRIX.md` §T7 (PK-01..05) и §T8-prep (PK-06..09).

**Сужение после проб 25–26 (PK-06..09):** интерактивная часть сессии —
ТОЛЬКО S6–S7 (выделение строки + «Открыть» в панели). Ввод пути фоном
возможен: у каждого контрола рядом с кнопкой есть редактируемое поле
(PK-07) — владелец вписывает путь руками, либо embedded-WDIO заполняет его
драйверно (PK-08: elementSendKeys → React onChange, ноль краж фокуса).
Голый AXSetValue на React-инпуты не работает (PK-06). Протокол ниже
остаётся каноничным для пикерной приёмки; замена S4→«вписать путь в поле»
превращает сценарий в фоновый.

| P2 | Артефакт: `target/release/bundle/macos/RimLoc GUI.app` | бинарник есть; иначе `testlab/build/build-automation-react.sh` |
| P3 | База памяти: `defaults read com.rimloc.gui NSNavLastRootDirectory` | old_value записан в лог (нет значения — зафиксировать «unset», в конце delete) |
| P4 | Окно приложения кадром `348,70,980x640` (PICKERS_FRAME по умолчанию) | окно видно целиком, поверх других |

## 1. Контролы (источник: CONTROLS, `lane_native_pickers.py`)

| id | Экран (сайдбар RU/EN) | Кнопка-лейбл (RU / EN) | Поле readback | Тип | Таргет |
|----|----------------------|------------------------|---------------|-----|--------|
| ex.pick | Существующий перевод / Existing translation | Папка существующего перевода / Existing translation folder | то же | dir | `pack-a` |
| ex.po-pick | Существующий перевод | Импорт из PO-файла / Import from a PO file | то же | file | `po-pack/pack.po` |
| be.pick | Сборка и экспорт / Build & export | Каталог вывода / Output directory | то же | dir | `out-dir` |
| diag.pick | Диагностика / Diagnostics | Каталог вывода / Output directory | то же | dir | `out-dir` |
| cmp.old-pick | Сравнение / Compare | Старая версия / Old version | то же | dir | `pack-a` |
| cmp.new-pick | Сравнение | Новая версия / New version | то же | dir | `pack-b` |
| wizard.pick | Экран проектов → модалка «Новый проект» / New project | Выбрать папку мода / Pick the mod folder | Путь к модам / Mod path | dir | `pack-a` |

- Кнопка внутри `<label>` именуется текстом ЛЕЙБЛА (собственный «Выбрать…» глотается
  WebKit) — искать/давить по лейблу из таблицы; наличие кнопки = сигнал прихода на экран.
- `be.pick` и `diag.pick` имеют одинаковый лейбл «Каталог вывода» — перед нажатием
  сверять активный экран по сайдбару.
- ex.pick / ex.po-pick / be.pick рендерятся только с открытым проектом → порядок:
  сначала `wizard.pick` (bootstrap: выбор `pack-a` → «Далее»… → «Создать проект»),
  затем остальные экраны.

## 2. Сценарии (× 7 контролов)

| Сценарий | Preset `NSNavLastRootDirectory` (`defaults write com.rimloc.gui … -string`) | Что подтверждаем | Ожидаемый readback |
|----------|-----------------------------------------------------------------------------|------------------|--------------------|
| memory | `<fixture>/po-pack` | панель открылась AT remembered root | dir: `<fixture>/po-pack`; ex.po-pick: `<fixture>/po-pack/pack.po` |
| path | таргет контрола (file → родитель `po-pack`) | выбор своей таргет-папки + write-back памяти | абсолютный путь таргета (`pack-a` / `out-dir` / `pack-b`) |
| cancel | таргет контрола | «Отмена» не меняет состояние | readback-after == readback-before байт-в-байт |

## 3. Пошаговый протокол (на контрол × сценарий)

| Шаг | Действие | Фиксация / критерий |
|-----|----------|---------------------|
| S1 | Открыть экран по сайдбару (wizard.pick: «Новый проект») | кнопка-лейбл контрола присутствует |
| S2 | Записать readback-before (значение поля из §1) | текст поля в лог |
| S3 | Preset памяти сценария (§2) | команда + preset в лог |
| S4 | Нажать кнопку-лейбл контрола | NSOpenPanel открылся |
| S5 | Health-гейт: popup «Где:/Where:» непуст и = preset; кнопка «Открыть» Enabled | PNG + panel-tree.json сразу; пустой Where: → деградация §6 (PK-03), round не считать пройденным |
| S6 | ИНТЕРАКТИВНО: выделить строку таргета (ex.po-pick — файл `pack.po`) | строка выделена — то, что AX недоступно (PK-01) |
| S7 | Дождаться Enabled «Открыть» (свежий preset грузит директорию; клик по disabled = тихий no-op) и нажать | panel-gone; в интерактиве фокус у панели есть (снимает PK-02) |
| S8 | readback-after | memory/path: == ожиданию §2; ex.po-pick: `<fixture>/po-pack/pack.po` (закрывает PK-05) |
| S9 | Только path после успеха: `defaults read com.rimloc.gui NSNavLastRootDirectory` (до 6× с паузой 1 c) | хвост == имени выбранной папки → write-back подтверждён |
| S10 | wizard.pick: после confirm модалка уходит на шаг 1, поле демонтируется | «Назад» возвращает шаг 0 с полем = выбранный `pack-a`; «Далее»… → «Создать проект»; закрытие «Отменой» |
| S11 | Здоровье приложения под модалкой | не упало/не зависло; web-контролы отвечают после закрытия панели; frontmost-журнал пуст (ноль перехватов фокуса) |

Cancel-сценарий: S1–S5, затем «Отмена» → панель исчезла; S8: readback-after ==
readback-before («cancel must not change state»). Отмена только кнопкой — без Escape.

## 5. Критерии прохода (зелёный T8)

| # | Критерий |
|---|----------|
| 1 | 7/7 × 3 сценария: панель открылась AT preset (Where: = preset), confirm сработал, readback == ожиданию §2 |
| 2 | ex.po-pick: строка `pack.po` выделена и подтверждена → readback `<fixture>/po-pack/pack.po` (PK-05 закрыт) |
| 3 | path: write-back — NSNavLastRootDirectory после пика заканчивается именем выбранной папки |
| 4 | cancel: панель закрыта «Отменой», readback байт-идентичен, состояние не тронуто |
| 5 | здоровье под модалками: ноль падений/зависаний, ноль перехватов фокуса, wizard-модалка закрывается «Отменой» |
| 6 | память восстановлена до old_value (P3) по завершении |

Итог-аналог exit-кода lane: 0 = всё выше; 2 = есть деградации (ремедия §6, повторить);
1 = реальные провалы или перехват фокуса.

## 6. Деградации и fallback (UI_DEFECTS_MATRIX PK-01..05)

| PK | Явление | Поведение в T8 | Fallback / ремедия |
|----|---------|----------------|--------------------|
| PK-01 | Строки NSBrowser не отдаются в AX (колонки без детей; строки видны только визуально) | S6 делает человек/CUA мышью; AX-навигацию по строкам не использовать | программный спуск по строкам считать неуспешным; опора на Where:/память |
| PK-02 | Кнопки панели игнорируют AXPress вне фокуса (err=0, no-op); программная активация отклонена | сессия интерактивная, панель frontmost — обычные клики работают | если «Открыть» не сработал — клик мышью, не AXPress |
| PK-03 | Начальная локация ведёт по security-scoped bookmark (NSOSPLastRootDirectory); NSNav-пресеты живут только при валидном bookmark/health; `defaults`-фабрикаты не принимаются | пустой Where: + перманентно disabled «Открыть» = деградед-состояние | один реальный выбор папки в RimLoc (любая сессия) регенерирует bookmark → панели здоровые → повторить round; до 3 попыток с отменой и переоткрытием, потом честно фиксировать деградацию |
| PK-04 | Приход панели по контролю и cancel-безопасность AX-верифицируемы (lane 9/9) | повторяются как S5/S8/cancel — регрессия здесь = реальный дефект UI | оформлять как провал round, не как деградацию |
| PK-05 | Выделение файл-строки + Open confirm через AX отложено на T8 | главный пункт сессии: S6–S8 для ex.po-pick | если `pack.po` не выбрать — стоп: round.json + PNG, не «зелёнить»; known-limitation AX-полосы (возврат DIR вместо pack.po) в интерактиве проходом НЕ засчитывать |
| PK-06 | AXSetValue не меняет React controlled inputs (err=0, значение пустое) | не использовать для заполнения полей | WebDriver-ввод (PK-08) или ручной ввод владельцем (PK-07) |
| PK-07 | У каждого пикера рядом с кнопкой есть редактируемое поле пути (`ex.dir`, `be.outdir`, …) | путь можно вписать руками — панель не обязательна для флоу | интерактив сжимается до проверки самой кнопки-пикера |
| PK-08 | Embedded WDIO (TCP 4445) заполняет React-инпуты фоном: elementSendKeys → onChange, round-trip; watchdog 61 сэмпл — 0 краж фокуса | фоновая секция A — путь WDIO-каналом | см. `docs/development/testing/WDIO_EMBEDDED_SPIKE.md` |
| PK-09 | Итоговый интерактивный остаток T8 | только S6–S7 по 7 контролам (~10 минут) | всё остальное — лана + WDIO фоном |

Bootstrap-деградация: здоровой панели нет в 3 попытках → закрыть модалку «Отменой»,
сначала покрыть ungated-контролы (`cmp.old-pick`, `cmp.new-pick`, `wizard.pick`);
gated (`ex.pick`, `ex.po-pick`, `be.pick`, `diag.pick`) — после ремедии PK-03.

## 7. Завершение

1. Закрыть wizard-модалку «Отменой», если открыта (только кнопки, без Escape).
2. Закрыть приложение; через ~2 c (cfprefsd) вернуть память:
   `defaults write com.rimloc.gui NSNavLastRootDirectory <old_value>` (или delete, если unset).
3. Свести итоги: rounds/passed/degraded/failed + focus_events; приложить report.json и каталог доказательств.
4. Вернуть фокус прежнему frontmost-приложению.
